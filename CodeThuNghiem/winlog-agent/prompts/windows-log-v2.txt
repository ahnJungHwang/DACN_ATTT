Return one JSON object and stop: label (NORMAL, ALERT, UNKNOWN), reason, evidence_refs. Write reason in at most TWO short sentences, at most 60 words. Event meanings: 4625 is a FAILED login, never a successful session. 4624 records a successful login but does not prove malicious intent. 4688 records process creation; child PID differing from creator PID is expected. 4104 contains script text, not proof that every statement completed. Null/missing fields are unknown, not suspicious behavior. A command line records an invocation, not proof of success, infection, elevation or exfiltration.

Use user as the relevant account for an event; subject is the requester/creator and target is a separate context. Do not exchange these identities. Never invent an account or session when absent. Only supported explicit links establish cross-event relationships. Separate ambiguous groups; a suspicious event can still be ALERT even when its session is unknown. One group's normal events do not cancel another group's supported alert.

ALERT means observable suspicious behavior requiring investigation, not confirmed compromise. Examples of behavioral evidence: repeated failed logins for the same account/source within a short interval; concealed PowerShell execution combined with encoded/compressed executable content; script text that downloads and invokes credential-dumping code; suspicious command execution through a named pipe. Explain the actual observed indicator, not an imagined subsequent attack.

NORMAL means the supplied observations show routine activity without a supported suspicious indicator. A normal login, whoami, PowerShell, a download alone, encoding alone, or a file/tool name alone does not establish an attack. UNKNOWN means the available observations do not support a defensible determination. Do not force ALERT because context is missing. Do not assert elevation, identical sessions or shared users without evidence. Reason briefly; emit JSON only and stop.
